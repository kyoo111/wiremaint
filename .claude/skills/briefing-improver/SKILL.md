# briefing-improver: 브리핑 생성 → 검증 → 이슈 → 처리 → 문서 정리

매일 브리핑을 생성하고, 그 결과물을 자동으로 검증·개선하는 완전한 루프를 실행한다.
아래 4단계를 순서대로 실행한다.

## 1단계 — 오늘 AI 브리핑 생성

ai-daily-report 스킬을 실행하여 HTML 브리핑을 생성한다.

```
"오늘 AI 브리핑 만들어줘"
```

완료 조건:
- [ ] `C:\Users\Admin\Desktop\ai_daily_report\reports\YYYY-MM-DD_ai_report.html` 파일 생성됨
- [ ] 10~20개 항목, 6개 카테고리, 국내 4개 이상 포함

## 2단계 — 브리핑 검증 + GitHub 이슈 등록

issue-writer 스킬을 실행하여 최신 브리핑을 검증하고 문제점을 GitHub 이슈로 등록한다.

검증 기준:
- 30일 초과 자료
- 수치 오류
- 국내 항목 30% 미만
- 카테고리 빈약 (1개뿐인 경우)
- 실무 영향 없는 항목
- 중복 기사
- 출처 없는 수치

완료 조건:
- [ ] 문제점이 있으면 GitHub 이슈로 등록
- [ ] 문제가 없으면 "검증 완료, 발견된 문제 없음" 알림

## 3단계 — 열린 이슈 처리

issue-runner 스킬을 실행하여 GitHub 이슈를 순서대로 처리한다.

각 이슈마다:
1. 처리 계획 댓글 작성
2. `scheduled-task-prompt.md` 수정
3. 커밋 + 푸시 (`closes #번호`)
4. 자동으로 이슈 Close

완료 조건:
- [ ] 모든 이슈가 Close됨
- [ ] 또는 열린 이슈가 없으면 "처리할 이슈 없음" 알림

## 4단계 — 프로젝트 문서 최적화

doc-optimizer 스킬을 실행하여 프로젝트 문서를 최적화한다.

작업 내용:
- CLAUDE.md, SOUL.md, README.md 상태 파악
- 역할 분리 (중복 제거, 링크로 참조)
- 낡은 내용 정리
- GitHub 커밋 + 푸시

완료 조건:
- [ ] 세 문서의 역할이 명확하게 분리됨
- [ ] 중복 제거됨
- [ ] 낡은 내용 정리됨
- [ ] GitHub에 커밋·푸시됨

## 최종 완료 조건

- [ ] 1단계: 브리핑 HTML 파일 생성
- [ ] 2단계: 문제점 이슈 등록 (또는 문제 없음)
- [ ] 3단계: 열린 이슈 모두 처리 (또는 이슈 없음)
- [ ] 4단계: 문서 최적화 완료
- [ ] 전체 과정 결과를 표로 보고
