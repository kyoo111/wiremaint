# doc-optimizer: 문서 최적화

프로젝트 문서를 역할별로 분리하고, 중복을 제거하고, 낡은 내용을 정리한다.
아래 4단계를 순서대로 실행한다.

## 1단계 — 현재 상태 파악

프로젝트 루트의 모든 `.md` 파일을 찾아 읽는다.

각 파일에 대해 파악할 것:
- 파일명과 경로
- 현재 담긴 내용의 종류 (규칙, 목적, 사용법, 히스토리 등)
- 마지막으로 실제 내용이 업데이트된 시점 (git log 또는 내용 추정)

파악 후 아래 형식으로 현황 요약을 작성한다:

| 파일 | 현재 담긴 내용 | 문제점 |
|---|---|---|
| README.md | ... | 중복, 낡은 내용 등 |

## 2단계 — 역할 분리

문서마다 역할을 하나씩 배정한다. 한 사실은 한 문서에만 존재해야 한다.

권장 역할 분리:

| 문서 | 역할 |
|---|---|
| `SOUL.md` | 왜 만들었나, 목표, 철학 — 변하지 않는 것 |
| `README.md` | 무엇인가, 어떻게 쓰나, 구조, 실행 방법 — 처음 보는 사람을 위한 것 |
| `CLAUDE.md` | Claude가 이 프로젝트에서 따라야 할 행동 규칙 — 경로, 명령, 규칙 |

프로젝트 성격에 따라 역할은 달라질 수 있다. 사용자에게 역할 배정안을 보여주고 확인받은 뒤 진행한다.

## 3단계 — 중복 제거 및 최소화

역할이 정해졌으면 각 문서를 다시 쓴다.

규칙:
- 한 사실은 한 문서에만 둔다. 다른 문서에서 참조가 필요하면 링크로 대체한다.
- 설명이 코드나 파일명으로 이미 자명한 내용은 삭제한다.
- 두 문서에 같은 내용이 있으면 더 적합한 역할의 문서에만 남긴다.
- 표, 리스트, 코드블록을 활용해 산문을 최소화한다.

## 4단계 — 낡은 내용 정리

삭제 또는 이동 대상:
- 이미 코드나 git 히스토리로 확인 가능한 내용 (예: "2025년 1월에 추가함")
- 더 이상 사용하지 않는 경로, 명령, 변수명
- TODO/메모성 내용 (GitHub 이슈로 옮기거나 삭제)
- 주석으로만 남아있는 계획 (실행했으면 삭제, 안 했으면 이슈 등록)

낡은 내용을 발견하면 삭제 전에 사용자에게 목록을 보여주고 확인받는다.

## 완료 조건

- [ ] 모든 `.md` 파일의 역할이 명확하게 분리되어 있다
- [ ] 동일한 사실이 두 문서에 중복되지 않는다
- [ ] 각 문서를 읽었을 때 다른 문서 없이도 해당 역할의 정보를 충분히 얻을 수 있다
- [ ] 낡거나 무의미한 내용이 제거되었다
- [ ] 변경 후 GitHub에 커밋·푸시한다 (`docs: 문서 역할 분리 및 최적화`)
