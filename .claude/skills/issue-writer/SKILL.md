# issue-writer: 브리핑 검증 후 GitHub 이슈 등록

가장 최근 생성된 AI 일일 리포트 HTML 파일을 읽고 약점을 찾아 GitHub 이슈로 등록한다.

## 1단계 — 최신 리포트 파일 찾기

`C:\Users\Admin\Desktop\ai_daily_report\reports\` 에서 가장 최근 날짜의 HTML 파일을 읽는다.

## 2단계 — 아래 기준으로 약점 검증

| 검증 항목 | 기준 |
|---|---|
| 오래된 자료 | 발행일이 30일 초과하거나 URL/내용에서 이전 연도가 확인되면 문제 |
| 수치 오류 | 배수·퍼센트·금액 등 숫자가 본문 내용과 맞는지 직접 계산해서 확인 |
| 국내 항목 부족 | 전체 항목 중 국내 항목이 30% 미만이면 문제 |
| 카테고리 빈약 | 항목이 1개뿐인 카테고리가 있으면 문제 |
| 관련성 낮은 항목 | IT 전략기획 실무와 3개월 내 관련 없는 항목 |
| 중복 기사 | 같은 사건을 다른 출처로 2번 이상 다룬 경우 |
| 출처 없는 수치 | 구체적 수치가 있는데 출처 URL이 없는 경우 |

## 3단계 — 발견된 약점마다 GitHub 이슈 등록

GitHub 저장소: `kyoo111/wiremaint`

각 약점에 대해 아래 형식으로 이슈를 생성한다:

```
gh issue create --repo kyoo111/wiremaint \
  --title "[문제를 한 줄로 요약]" \
  --body "## 문제\n[구체적으로 어떤 항목에서 어떤 문제가 있는지]\n\n## 개선 방향\n[어떻게 고치면 되는지]"
```

약점이 없으면 이슈를 등록하지 않고 "검증 완료, 발견된 문제 없음"이라고 알린다.

## 4단계 — 결과 요약

등록된 이슈 번호와 제목을 표로 정리해서 보여준다.
